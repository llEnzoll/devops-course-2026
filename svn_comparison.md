# Git и SVN: ответы на вопросы

## 1. Почему ветвление в Git «дешёвое», а в SVN «дорогое»?

**Git:** ветка - это просто указатель на коммит. Создаётся мгновенно и локально, без копирования файлов. Граф истории позволяет надёжно сливать ветки.

**SVN:** ветка - это папка в репозитории (`svn copy`). Операция выполняется на сервере и создаёт общую ревизию. Слияния исторически были сложными и ненадёжными.

## 2. Можно ли в SVN сделать коммит без интернета?

**Нет**, если сервер недоступен: SVN централизованный, коммит сразу уходит на сервер, локальной истории нет.

**Исключение:** сервер в локальной сети или репозиторий на своём диске (`file://`).

**Сравнение с Git:** коммит локальный, сеть нужна только для `push` / `pull`.

## 3. Когда SVN может быть предпочтительнее Git?

- Большие бинарные файлы (ассеты, CAD, видео)
- Блокировка файлов, которые нельзя слить
- Частичный checkout подпапок в огромном репозитории
- Права доступа по папкам
- Простота для нетехнических участников (дизайнеры, авторы документации)
- Легаси-инфраструктура и строгий централизованный контроль
